## How to contribute

The general way to contribute is to fork the main repository on GitLab:
1. Fork the repository and `git clone` it.
1. Prepare your environment. Use `uv sync` to install all required dependencies, including development dependencies and create virtual enviroment.

1. Make your changes
    1. Format them
        ```bash
        uv run ruff format
        ```
    1. Test them
        ```bash
        uv run pytest
        ```
    1. Run pre-commit hooks
        ```bash
        uv run pre-commit run --all-files
        ```
    1. Commit them and push them to your fork.
1. You can open a pull request on GitHub when you're satisfied.

Here is a summary:

```bash
### Create Python virtual environment
uv sync

# <Make your changes>

### Format them
uv run ruff format
### Test them locally
uv run pytest
### Run pre-commit
uv run pre-commit run --all-files

# <Commit your changes>
# <Push your changes>
# <Open a PR!>
```

## Source code contributions
### Testing
__All contributions to the source code of sci-cli should be documented and unit-tested__.
To run tests, use:
```bash
uv run pytest
```
To run tests with coverage reports in HTML, use:
```bash
uv run pytest --cov=sci_cli --cov-report html
```
The report will be generated in the  `htmlcov/index.html` file.

## Formatting and Linting

### Docstrings
Docstrings should follow the [NumPy Style](https://numpydoc.readthedocs.io/en/latest/format.html), have a look at other docstrings in the codebase for examples.
Examples in docstrings can be bery useful, don't hesitate to add some!

The documentation is autogenerated using [`mkdocs`](https://github.com/mkdocs/mkdocs).
To start a local server, run
```bash
uv run --group docs mkdocs serve --livereload
```

### Formatting, Linting, Type Checking

The code should be automatically formatted using [`ruff`](https://github.com/astral-sh/ruff).
To format the code manually, run
```bash
uv run ruff format
```

[`ruff`](https://github.com/astral-sh/ruff) is also used for code linting.
To check the code, run
```bash
uv run ruff check
```
To fix issues automatically, run:
```bash
uv run ruff check --fix
```

The VS Code [ruff extension](https://marketplace.visualstudio.com/items?itemName=charliermarsh.ruff) is recommended for linting and automatic formatting during development.

For type checking, [Pyright](https://github.com/microsoft/pyright) is used.
The VS Code [Pylance extension](https://marketplace.visualstudio.com/items?itemName=ms-python.vscode-pylance), powered by Pyright, is also recommended.

To run type checking, use:
```bash
uv run pyright
```

### Before commit

All the steps above (`ruff format`, `ruff check`, `pyright`) can be executed automatically using the `pre-commit` package.
First, install the hooks:
```bash
uv run pre-commit install
```
Now `pre-commit` will run automatically when executing the `git commit` command.
However, you can run it manually as well:
```bash
uv run pre-commit run
```
Or, to run all hooks on all files, use:
```bash
uv run pre-commit run --all-files
```


### Working with `uv` package manager

To synchronize the packages in your virtual environment and lock file, use:
```bash
uv sync
```
To add a new package dependency to the project, use:
```bash
uv add <packagename>
```
To add a dependency required only during development, use the `--dev` flag:
```bash
uv add <packagename> --dev
```
